# Agent Platform

## 目标

以飞书小C为统一入口，建立可扩展、可迁移的多Agent平台，核心目标是显著提升用户的工作效率，同时支持隔离的个人记录和临时咨询。

## 已确认入口与边界

- 小C单聊是总入口、跨主题协调和系统管理入口。
- 只有用户与小C的主题群用于区分信息，每个群绑定独立Workspace、专属Skill和记忆范围。
- 多人群中仅处理明确 `@小C` 的消息；不得自动读取或写入私人Workspace记忆。
- 错投信息应得到简短响应并被引导到专属群；未经确认不得污染当前Workspace或跨Workspace写入。
- 工作、个人、临时咨询、系统管理为隔离Domain；跨域敏感读取需要明确授权。

## Agent与资源

- 当前主控逻辑角色为 `primary_orchestrator`，现阶段映射到Codex，未来允许替换。
- WorkBuddy 5.3.5已在当前设备发现，定位为桌面执行候选，接口与权限仍需验证。
- DeepSeek Harness `@deepseek-ai/dsh` 0.1.0-rc.7已在WorkBuddy Node运行时发现，定位为成本优化执行候选，运行接口仍需验证。
- Agent、Skill、插件、模型和设备都通过Registry及适配器接入，不得把具体实现写死在Workspace业务规则中。

## 记忆与信息接入

- 飞书文档、表格、聊天、日历、会议、任务、附件、网络信息和用户实时输入应通过Connector接入。
- 历史信息采用元数据优先、分批读取、去重、索引和增量同步，不把全部原文直接写入长期记忆。
- Agent只提交 `memory.proposal`；正式长期记忆由单一Memory Writer按审计、revision检查和原子替换协议写入。
- 工作和个人记忆隔离；临时咨询默认不持久化。

## 成本与紧急模式

- 支持standard、deep、sprint、maximum四种执行模式。
- 日常按需加载Skill、插件、记忆和Artifact片段，优先使用规则、缓存和低成本执行器。
- maximum模式可扩大Token、并行度、检索和交叉验证，但不能扩大权限、取消审批或突破工作/个人隔离。

## 自学习

- 平台可以学习稳定偏好、高频工作流、Agent路由效果、Token成本和能力缺口。
- 可自动生成候选、沙箱测试和影子运行；安装未知代码、扩大权限、启用外部写入、更换主控或采用新付费服务需要批准。
- Skill和插件推荐应可解释、可审计、可灰度、可回滚，并控制主动推荐频率。

## 跨设备与迁移

- 当前设备硬件有限，是临时Gateway、控制面和Memory Writer主节点。
- 其他设备只作为执行节点，不直接消费飞书入口或写正式记忆。
- 未来迁移到高配置主设备时采用Standby、影子运行、最终同步、单主切换和旧设备回滚保留。
- 任意时刻最多一个活动Gateway和一个正式Memory Writer。

- 基线包含Domain、Workspace、Agent、Device、执行模式、记忆和自学习策略，以及任务与记忆候选协议。
- 已实现并验证本地Task Store、任务状态机、执行预算、Agent/设备选择、Capability Gap、Memory Proposal队列和飞书事件标准化适配器。
- 已验证DeepSeek Harness CLI及headless接口；尚未执行真实模型任务。
- 已启用“无人值守但受控”的Codex心跳自动推进：自动执行本地验证、静态分析和平台目录内可逆变更；付费模型、飞书OAuth、桌面控制、外部发送、权限扩张和主节点切换进入审批队列。

- 首个自动规划周期已完成3项安全任务：离线控制面验证、Bridge旁路事件契约和Knowledge Index数据/同步水位模型。

- 基线不包含密钥，未发送飞书消息，未启动或重启外部Agent服务。
